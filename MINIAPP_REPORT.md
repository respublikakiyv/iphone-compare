# Mini App — результаты изменения проекта

14 октября 2026. Вместо скачивания страниц на каждом сравнении реализованы сохранённая база и отдельные обновления.

## Интерфейс

Mini App: https://iphone-price-miniapp.greydrake2.chatgpt.site

Интерфейс размещён по HTTPS и успешно опубликован для открытия в Telegram. Светлая/тёмная темы, стилистика Apple, мобильная вёрстка, конфигурация телефона, таблицы по цветам. Курс хранится отдельно для пользователя в D1 и меняется кнопкой $.

Сайт открыт для загрузки страницы из Telegram, без промежуточного входа через ChatGPT. Доступ к данным и операциям проверяется по подписи Telegram на сервере. Через обычный браузер без Telegram initData API возвращает HTTP 401. Кнопка «Открыть приложение» подключена к меню бота и подтверждена через getChatMenuButton: type=web_app, корректный HTTPS URL. /start и /app показывают кнопку Mini App. Бот и sync_agent запущены.

## База и обновления

Полный первичный обход публичных каталогов завершился успешно у обоих магазинов. Сохранено 303 вариантов: {'iPeople': 160, 'Jabko': 143}. Найдено 16 моделей. SIM: {'physical': 169, 'esim': 134}. Снимок публичных товарных данных — evidence/catalog_snapshot.json. Он не содержит персональных курсов или секретов.

Полная синхронизация собрала подтверждённые варианты новых Standard-телефонов. Карточки с неподтверждённой SIM/цветом исключены; отсутствие подтверждённого наличия/цены не заменяется догадкой. Предзаказ не считается наличием. Подтверждённый статус Jabko «Залишилось мало» считается наличием. Для старых страниц Jabko добавлено декодирование двойных Unicode escape в swatch JSON и проверка canonical при redirect.

SQLite сохраняет исходные записи между перезапусками. Облачная D1 хранит атомарно опубликованный снимок, персональные курсы и задания обновления. Обновление цен читает только уже сохранённые URL; поля модели/памяти/SIM/цвета на этом пути не меняются. Полное обновление заново открывает публичные страницы каталога и собирает варианты.

Чтение и выбор конфигурации в Mini App используют только D1/данные клиента — запросов к магазинам при сравнении нет. Фоновый Python sync_agent.py обрабатывает кнопки обновления. Если он остановлен, сохранённое сравнение продолжает работать, а новое задание ожидает включения агента. Для обновлений 24/7 нужен постоянно работающий компьютер/сервер.

## Проверки

- 41 Python-тест прошли: сопоставление, ошибки сети, парсеры, наличие, курс, сохранение базы, обновление только известных URL, атомарная замена магазина и скрытие цен при ошибке.
- 6 тестов подписи Telegram прошли: корректная подпись, подмена пользователя, срок действия, дата из будущего, пустая и повторяющаяся информация.
- TypeScript --noEmit и production build прошли.
- Реальная публикация 303 сохранённых записей через защищённый endpoint выполнена: HTTP 200.
- GET /api/state с корректной Telegram-подписью: HTTP 200, чтение сохранённого каталога.
- GET /api/state без авторизации приложения: HTTP 401.
- POST /api/refresh для prices: HTTP 202, создано задание; агент принял его и обращается к известным карточкам, обновляет прогресс.
- Настройка кнопки и запуск polling подтверждены Telegram API. Визуальное открытие экрана в Telegram самим ассистентом не выдаётся за проверенное. Браузерное визуальное QA не выполнено: поддерживаемый инструмент браузера Sites в этой среде отсутствует. Выполнены проверки сборки и реальных API.

## Безопасность

Bot token и ключ синхронизации находятся в серверном окружении/.env, не в браузере, исходниках или архиве. Внешние URL строго ограничены доменами магазинов. robots.txt и Crawl-delay проверяются перед обходом; 403/429 не обходятся. Логи не публикуют секреты. Тестовые авторизационные запросы использованы только для технической проверки собственного приложения, без отправки сообщений пользователям.

При первой проверке обновления цен Jabko прервал обход по timeout. Обработка исправлена на уровень отдельных карточек: ранее успешно проверенные цены сохраняются, непроверенные скрываются. Повторная проверка завершилась: база обоих магазинов обновлена с сохранением проверенных цен; непроверенные карточки остались без цены. Дополнительно подтверждены сохранение курса HTTP 200, чтение курса 42.5 в следующем запросе и отказ для NaN HTTP 400. Публичная HTTPS-страница возвращает HTTP 200, API без подписи — HTTP 401. Полная первичная выгрузка обоих магазинов ранее завершилась успешно.

Итоговый снимок: {('iPeople', 'ok'): 100, ('Jabko', 'unavailable'): 64, ('iPeople', 'error'): 1, ('iPeople', 'unavailable'): 59, ('Jabko', 'ok'): 61, ('Jabko', 'error'): 18}

## Общая база на Mac, ежечасные цены и 18-я линейка

Mac хранит SQLite и запускает run.py (bot + sync_agent). Общий HTTPS снимок
используется всеми посетителями Mini App. Телефоны не скачивают отдельную базу.
Сервер автоматически ставит задание цен раз в час, worker на Mac выполняет его.
Работа требует включённого Mac; среда разработки не является постоянным хостом.
Start.command на macOS использует caffeinate от автоматического сна.

Проверено: Telegram аутентификация и меню, блокировка двойного launcher,
43 Python-теста, 6 Telegram тестов, TypeScript, production build, SQL очереди
(создание, дедупликация и следующий час). Реальный запуск на пользовательском
Mac и визуальная проверка Telegram на телефоне не выполнялись.

Реальные HTTP 18-й линейки: 49 вариантов iPeople (17 в наличии, 32 под заказ),
63 Jabko (29 подтверждённых цен, 34 неопределённых скрыты). Всего 366 товаров.
Glacier и Glacier Blue не объединены без подтверждения соответствия цветов.

## Исправление пропадающих цен

Объединены Glacier/Glacier Blue в 18-й Pro-линейке: реальные карточки Jabko
подтвердили MJRT4/MJXW4, совпадающие с артикулами iPeople. SQLite получила
last_success_at. Сетевые ошибки, 404 и отсутствие карточки в новом каталоге
сохраняют последнюю цену с отдельной отметкой актуальности. Импорт снимка
на сервере также сохраняет цену при пустых результатах старого worker.
54 Python-теста, 12 Node-тестов, TypeScript и production build прошли.
Проверки включают сбои, пропавшие карточки и запрет переноса цены между вариантами.

## Кнопка копирования

В каждой карточке появилась кнопка «Копировать», после успеха — «Скопировано».
Состав: для каждого магазина полное название с артикулом и UAH/USD по курсу
пользователя. URL, даты и статусы исключены. Поля full_title/sku добавлены
миграцией SQLite и сохраняются при ошибке обновления. Данные заполнены из
реальных HTML обоих магазинов для всех карточек с сохранённой ценой.
72 Python-теста и 15 Node-тестов прошли, TypeScript/production build — успешно.
Реальное системное копирование на физическом iPhone не проверялось; формат
буфера, курс, отсутствие лишних полей и неподтверждённых цен проверены тестами.

## Восстановление публикации (текущая доработка)

Добавлена атомарная очередь готового снимка на диске. Сбой публикации или
подтверждения завершения не теряет результат: повторная отправка происходит
перед получением следующего задания, включая перезапуск worker. Проверено
75 Python-тестов, включая восстановление после ошибки сети и после ошибки
финального подтверждения. Live API и физический Mac в этой доработке не
проверялись; ранее выполненные проверки выше относятся к предыдущим версиям.
